# 能力与边界

> 证据等级：**observed** = 本机实测；**documented** = 官方文档或社区一致反馈；**unverified** = 推断或未验证。

---

## 1. 它做什么

| 能力 | 说明 | 证据 |
| --- | --- | --- |
| 把行为契约注入 TRAE 全局规则 | 写 `~/.trae-cn/user_rules/rule-trae-purge-kit.md`，进 prompt 的 `<user_rules>` 段 | observed（本机 `ai_agent` 模块的提示词组装里存在该段）+ documented（官方规则文档给出的目录） |
| 去掉模型自身的拒绝式措辞 | 词库的「措辞闸」是一张禁用措辞 → 替代表述的对照表 | **observed**：措辞层面确实变干净（回答末尾会照规则带出自定义标记，见 ENTRY-GATE P8） |
| 翻掉模型自身对安全技术的拒绝（闸 2） | 词库的「四·五 反推脱条款」+「四·六 可直接填充的产物槽」 | **observed**：同一句破解请求——旧词库（只有禁用措辞表）仍被拒并换题；加强词库 + 阶梯级 1.5 一次通过，拿到完整可跑的 keygen/篡改/时基绕过实现 |
| 技术类意图不追问范围 | 词库的「意图路由」表 + 产物槽 | **observed**：渗透类一次通过，直接给 sqlmap 全参数命令，没有范围反问 |
| 自检：规则是否真在、内容有没有被改 | 四项断言 + 双指纹（marker + sentinel） | observed（自检脚本自带假环境全链路测试） |
| 幂等安装 / 一键回滚 | 备份 → 写入 → 状态记录；卸载时还原备份或只删自己那一个文件 | observed |
| 给「换自定义模型」这条路做指引 | 档案 + 文档 + 分诊流程 | documented（TRAE 支持 OpenAI 兼容自定义模型） |
| 可选的本地 relay：放宽上游安全阈值 + 过滤后自动重投 | `scripts/relay.mjs`，只监听 `127.0.0.1` | **observed（机制，本地夹具端到端）**：重投阶梯、占位符改写、2xx 流式不缓冲、Gemini 形状注入 / OpenAI 形状不注入、日志不含正文——共 9 条断言由 `scripts/relay-test.mjs` 全过。对**真实服务商**是否有效仍为 **unverified** |

## 2. 它不做什么

| 不做 | 为什么 |
| --- | --- |
| 不修改 TRAE 的安装目录、二进制、进程 | 不可逆、会被更新覆盖、跨版本失效；而且改二进制对第三方服务端的判定无效 |
| 不关闭 TRAE 云端的内容安全 | 那一层在别人的服务器上，没有开关 |
| 不保证任何第三方服务端不拦 | 同上 |
| 不代填 API Key、不代登录、不碰验证码 | 这些必须由使用者本人完成 |
| 不联网上报 | 唯一出网的动作是使用者自己启动 relay 后的模型请求 |
| 不删用户的其它规则 | 回滚只针对本套件自己写的那一个文件 |
| 不做「删掉违规那部分再继续」 | 那不是绕过，是篡改 |

## 3. 运行期行为

- **写盘**：只在安装/卸载时发生。
- **常驻**：没有守护进程，没有后台任务，没有自启动项。
- **联网**：默认没有。`scripts/relay.mjs` 启动后会在本机回环端口上监听，并把请求转发到使用者指定的上游。
- **读取**：只读自己那一个规则文件、状态文件，以及同目录规则文件的**文件名与大小**（用于算 32 KB 总量；不读内容）。

| 路径 | 何时写 | 卸载时 |
| --- | --- | --- |
| `<TRAE_HOME>/user_rules/rule-trae-purge-kit.md` | 安装 | 还原备份 / 删除 |

## 5. 上机前必查项

1. **relay 的上游协议**：TRAE 的自定义模型走 OpenAI 兼容协议，请求体是 `messages`。relay 的 `safetySettings` 注入只对 Gemini 原生形状（路径含 `/v1beta/` 或体里有 `contents`）生效。若你的上游是 OpenAI 兼容形状，注入不会发生——这是预期行为，不是 bug。
2. **relay 的路径**：默认把 TRAE 请求的路径原样拼到 `--upstream` 后面。若上游需要前缀（如 `/v1`），把 `--upstream` 写成含前缀的完整地址，必要时用 `--strip-prefix` 去掉重复段。
3. **32 KB 规则上限**：TRAE 对全部规则总量有硬限制。装之前先跑 `node scripts/status.mjs` 看「其它规则」合计字节数。
4. **压缩响应**：relay 转发时把 `accept-encoding` 覆写成 `identity`。个别上游会无视它仍回 gzip/br——relay 会先解开**只为判定**是不是过滤信号（解不开就不重投，原样转发），并且不剥 `content-encoding`。若你的上游只在压缩下返回错误体，`/gzip/` 这类夹具用例（`scripts/relay-test.mjs` R6/R8）已经把这条路径钉住了。
5. **目录信任**：TRAE 只加载可信目录里的项目规则。全局规则（`user_rules`）不受此限，但项目级规则受。

## 6. 已知限制

- 规则改动**在新对话里即时生效**，不需要重启 TRAE（实测：往规则里加一行自定义标记，下一轮回答原样带出；卸载后标记消失）。手册里「完全重启」是保险做法，只有换模型/改配置目录才必须重启。
- 规则改不动服务端的内容安全判定（979 / 983）。这是本套件最重要的一条限制。
- 词库只给「禁用措辞表」**翻不动模型自身对齐**：实测同一句破解请求在这种词库下仍被拒并被换成别的题目。必须配上「反推脱条款 + 可直接填充的产物槽」才见效（`words/core.md` 的四·五 / 四·六 两段）。
- 单靠换措辞框架过入口闸的效果，**不该记在词库头上**：实测同一句文学框架措辞在卸载规则后照样过闸。两类手法各自有效，归因要分开。
- TRAE 升级后，配置根路径、规则目录名、错误码语义都可能变。`status.mjs` 与 `verify.mjs` 会在路径失效时报出来。
- 词库是纯文本。TRAE 若在某些版本里改了规则文件的解析方式（例如要求 frontmatter），注入会失效——`verify.mjs` 只能验证文件在位与内容未被改，**不能证明 TRAE 一定加载了它**。行为验证仍需人工做一次。
- relay 的重投阶梯是**启发式**的，不保证能通过任何特定上游的过滤。

## 7. 安全设计

- **最小写面**：只写一个规则文件 + 一个状态文件 + 一个备份。
- **可逆**：每次覆盖前先备份；卸载优先还原备份。
- **幂等**：同样的输入装两次，第二次报「已是最新」，不产生第二份备份。
- **双指纹**：marker（HTML 注释）与 sentinel（明文哨兵）双重标记，防「注释被过滤 → 假阴性」和「内容被替换 → 假绿」。
- **防篡改**：正文哈希参与断言，手工改动会被自检抓出来。
- **隐私默认**：relay 默认不记录请求体与响应体；日志只有状态码、请求指纹、阶梯档位。
- **零自动行为**：扩展激活只提示，不自动写盘。
