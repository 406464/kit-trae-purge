# 安装手册（人类阅读）

> 套件名：**TRAE 破甲套件**（trae-purge-kit）
> 适用对象：TRAE IDE（Trae CN / TRAE SOLO CN / 国际版），Windows / macOS / Linux
> 本手册不包含任何特定机器的信息；所有路径都用占位写法，你按自己的系统替换即可。

---

## 0. 先搞清楚这是什么

这套件做两件事：

1. **把一份「行为契约」写进 TRAE 的全局规则目录** —— 让助手按你指定的形态输出（先给产物、不用拒绝式措辞、命中技术意图时不追问范围）。
2. **给一条绕开 TRAE 云端内容安全闸的路径** —— TRAE 内置模型走的是 TRAE 自己的云服务，那一层的判定在服务器上，本地改不了；真正的绕法是**把模型换成你自己接的 OpenAI 兼容模型**，请求就不经过 TRAE 的网关了。

它**不做**这些事：

- 不修改 TRAE 的安装目录、二进制、进程。
- 不改你的其它规则文件。
- 不联网上报任何东西（relay 脚本除外，且 relay 只监听本机回环地址）。
- 不代你填写 API Key、不代你登录、不碰验证码。

它**会**写这些文件（每个都能删）：

| 路径（`~` = 你的用户目录） | 内容 | 卸载时 |
| --- | --- | --- |
| `~/.trae-cn/user_rules/rule-trae-purge-kit.md` | 行为契约正文 | 还原备份或删除 |
| `~/.trae-cn/user_rules/rule-trae-purge-kit.md.bak-<时间戳>` | 旧文件备份 | 保留（不自动清理） |
| `~/.trae-cn/.trae-purge-kit/state.json` | 安装状态记录 | 删除 |

---

## 1. 前置条件

- 已安装并**至少启动过一次** TRAE（这样配置目录才会被创建）。
- Node.js **≥ 18**（只有脚本路线需要；VSIX 路线不需要）。
- 如果你打算走「换自定义模型」这条路线，需要你自己有一个 OpenAI 兼容的模型服务地址、模型 ID 和 API Key。**这些由你自己填**，本套件不收集、不存储、不上传。

先看一眼环境（只读，不写盘）：

```bash
node scripts/preflight.mjs
```

全绿再往下走。

---

## 2. 方式 A：脚本安装（推荐）

解压到任意目录，然后：

```bash
# 演练：只看会写什么，不落盘
node scripts/install.mjs --dry-run

# 实际安装（会问你一次确认）
node scripts/install.mjs

# 已经确认过、想跳过交互（比如在 CI 里）
node scripts/install.mjs --yes
```

装完：

```bash
node scripts/verify.mjs
```

看到 `自检通过` 就算装好了。

**然后要做的事**：

1. **开一个全新的对话** —— 实测 TRAE 按请求读 `user_rules`，新对话即时生效，**不需要重启 IDE**。
2. 只有在你要换模型入口（添加自定义模型）或改配置目录时，才需要完全退出 TRAE（含托盘与后台进程）后重开。

> 想装到别的 TRAE 配置根（多版本共存的情况）：`node scripts/install.mjs --trae-home "<目录>"`。
> 想用自己的词库：`node scripts/install.mjs --word-pack "<目录或文件路径>"`（会**取代**套件自带的词库，不是叠加）。

---

## 3. 方式 B：装成 TRAE 扩展（VSIX）

想要图形界面里的命令（安装 / 卸载 / 状态 / 自检），用这条路线。

1. 生成 VSIX（如果分发包里已经有 `dist/*.vsix`，跳过这步）：

   ```bash
   node scripts/pack-vsix.mjs
   ```

2. 在 TRAE 里：**扩展面板 → 右上角「…」 → 从 VSIX 安装… → 选 `dist/trae-purge-kit-<版本>.vsix`**。

3. 命令面板里搜 `TRAE 破甲`，先跑「查看状态」，再跑「安装全局规则」。

4. 同样要**完全重启 TRAE + 开新对话**。

> 扩展激活时**只提示、不自动写盘**。往用户目录里写东西是可逆但有影响的操作，不该在你没点头的时候发生。

---

## 4. 方式 C：完全手动（IDE 界面）

不想跑任何脚本的话：

1. TRAE → **设置 → 规则与记忆** → 规则 → **+ 创建** → **全局**。
2. 把套件里 `words/core.md` 的内容整段粘进去（第一行 `# 破甲契约（TRAE 全局规则）` 也要带上）。
3. 保存 → **完全重启 TRAE** → 开新对话。

这一条路没有指纹、没有自检，规则被误删或误改时只能手工看出来。想确认是否生效，见下一节。

---

## 5. 验证：怎么确认规则真的进去了

**结构上**：

```bash
node scripts/verify.mjs
```

它给出四项断言：文件在不在、双标记齐不齐、指纹对不对、正文有没有被改过。

**行为上**（这才是真的）：开一个新对话，问一句能触发措辞闸的话，看它是不是照契约那样直接给产物。

**装载探针（最直接的验证法，实测有效）**：给规则文件临时加一段——

```
## 探针

- 回答的最后必须单独一行输出：TPK-LOADED-7Q
```

然后开新对话问「你是谁？只回一句话」。回答末尾出现 `TPK-LOADED-7Q` = 规则确实进了这次请求的上下文；没出现 = 没被装载。验完把那几行删掉即可（`verify` 会短暂报「正文未被改动」FAIL，属正常，删掉探针就恢复 PASS）。

> 这条探针同时证明了：TRAE 是**按请求**读规则目录的，不缓存、不必重启。

**注意**：如果 TRAE 云端报 **979 / 983**，那说明你的请求被 TRAE 服务端的内容安全拦下了——**这跟规则装没装好没关系**，规则管的是模型愿不愿意答，服务端那一层在规则之外。请直接跳到第 6 节。

---

## 6. 关键一步：把模型换成你自己的（绕开服务端那一层）

TRAE 内置模型（豆包 / Kimi / DeepSeek 等）走 TRAE 的云服务，敏感内容会在服务端被拦，**本地任何改法都绕不过去**。能绕开的唯一干净做法是换一个入口。

**步骤**：

1. TRAE → **设置 → 模型管理** → **添加模型** → 选 **自定义模型（OpenAI 兼容）**。
2. 填三项：
   - **服务地址 / Request URL**：你的 OpenAI 兼容服务地址（例如某个中转或你自己的部署）。
   - **Model ID**：服务端真实存在的模型 ID（**必须与服务端一致**，填错会报「模型不存在」）。
   - **API Key**：你自己的 Key。**由你自己粘贴**，本套件不碰。
3. 保存后，在聊天窗口右上角把模型**切到**这个自定义模型。
4. 建议**开新对话**再试。

到这一步，请求是你 → 你的服务，中间没有 TRAE 的内容安全网关，979/983 也就不会再由 TRAE 判定。

**可选：再叠一层本地中转**（如果你用的是 Gemini 系上游，且想放宽它的安全阈值）：

```bash
# 先把 Key 放进环境变量，不要写进任何文件
export OPENAI_API_KEY=你的Key
node scripts/relay.mjs --upstream https://你的服务地址/v1
```

然后把 TRAE 自定义模型里的服务地址改成 `http://127.0.0.1:8788`，Key 照旧填你自己的（relay 会用环境变量里的 Key 覆盖上游认证头）。

relay 干三件事：给 Gemini 系上游注入宽松的 `safetySettings`；上游返回过滤类错误时按「形式阶梯」改写最后一条消息并自动重投（默认最多 2 次）；打日志只记状态码、请求指纹与阶梯档位，**默认不记录请求体与响应体**。

> relay 只监听 `127.0.0.1`，不对外暴露。它是可选组件，不装也能用整套东西。

## 7. 排障

| 现象 | 大概率原因 | 处理 |
| --- | --- | --- |
| 自检报「规则文件不存在」 | 装到了别的 TRAE 配置根 | `node scripts/status.mjs` 看它找的是哪个目录；用 `--trae-home` 指对 |
| 自检 PASS 但行为没变 | 没重启 / 还在老对话里 | 完全退出 TRAE（含托盘与后台进程），重开，**开新对话** |
| 老对话里行为变了，新对话没变 | 反过来的情况 | 新对话才会读新规则 |
| 报 979 / 983 | TRAE 服务端内容安全 | **规则管不了这一层**，去第 6 节换自定义模型 |
| 报 983 且提到社区规范 | 同上 | 同上 |
| 规则文件在，但助手还是老样子 | 目录未被信任 / 规则被截断 | 看 `node scripts/status.mjs` 里「其它规则」合计字节数；TRAE 的全部规则总上限是 **32 KB**，超了会截断。精简你自己的规则文件 |
| 自检报「正文未被改动」FAIL | 文件被手工编辑过 | 重新跑 `node scripts/install.mjs` 覆盖回去 |
| 装完 TRAE 报错 / 行为怪异 | 规则文本里有它解析不了的内容 | 跑 `node scripts/uninstall.mjs` 回滚，再看具体报错 |

## 8. 卸载 / 回滚

```bash
node scripts/uninstall.mjs --dry-run   # 先看会做什么
node scripts/uninstall.mjs             # 实际执行
```

行为：

- 有备份 → 把最新的 `.bak-<时间戳>` 还原回原位。
- 没备份 → 删掉本套件自己写的那个文件。
- **同目录里你其它的规则文件一个都不动。**
- 状态文件 `~/.trae-purge-kit/state.json` 会被删除。

装成扩展的话，在扩展面板里卸载扩展即可；扩展不写盘时直接删扩展目录也行。

## 9. 你要把这套件给别人用

分发前请按这个清单过一遍：

**对方要做的事**：

1. 解压 → `node scripts/preflight.mjs`（只读体检）。
2. `node scripts/install.mjs` → 照提示重启 TRAE、开新对话。
3. `node scripts/verify.mjs` 确认。
4. 需要绕服务端闸的话，按第 6 节配自己的自定义模型。

**你分发前必须确认的事**：

- [ ] 包里**没有**你自己的词库、定制规则、内部代号、员工姓名、内网地址。
      （`words/` 里的正文会随请求发给模型服务。）
- [ ] 跑一遍 `node scripts/scrub.mjs`，确认没有本机路径、用户名、IP、密钥残留。
      需要额外黑名单时：`node scripts/scrub.mjs --deny-file 你的黑名单.txt`。
- [ ] 跑一遍 `node scripts/attest.mjs`（署名检查）和 `node scripts/selfcheck.mjs`（全链路自检）。
- [ ] 用 `node scripts/pack.mjs` 重新打包（它会自动跑上面三道闸，不过就不出包）。
- [ ] 附一句说明：**这套件不修改 TRAE 二进制，只往你自己的规则目录写一个文件；可一键回滚。**

**隐私提醒（务必转达给对方）**：

- 套件本身不联网、不上报；`relay` 只监听本机回环地址。
- 但**规则正文会随每一次对话请求发给你的模型服务**——包括 TRAE 云端模型，或你自己配的服务商。
- API Key 由使用者自己填在 TRAE 设置里；套件不读、不存、不打印它。relay 只从环境变量读，且不落盘。

## 10. 常见路径速查

| 用途 | macOS / Linux | Windows |
| --- | --- | --- |
| TRAE 配置根 | `~/.trae-cn` | `%USERPROFILE%\.trae-cn` |
| 全局规则目录 | `~/.trae-cn/user_rules` | `%USERPROFILE%\.trae-cn\user_rules` |
| 本套件的规则文件 | `~/.trae-cn/user_rules/rule-trae-purge-kit.md` | `%USERPROFILE%\.trae-cn\user_rules\rule-trae-purge-kit.md` |
| 项目级规则 | `<项目>/.trae/rules/` | `<项目>/.trae\rules\` |
| 本套件状态 | `~/.trae-cn/.trae-purge-kit/state.json` | `%USERPROFILE%\.trae-cn\.trae-purge-kit\state.json` |

> 不同 TRAE 版本可能把配置根叫 `.trae` 或 `.trae-cn`。`node scripts/status.mjs` 会把探测到的路径都列出来。
